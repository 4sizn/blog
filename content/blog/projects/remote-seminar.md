> **근거 범위**: 이 글은 당시 Notion Project Experience에 남긴 서비스 설명·기간·담당 업무·기술 목록을 바탕으로 작성했다. 회사 소스, 운영 데이터, 세미나 내용과 참여자 데이터는 검토하거나 공개하지 않는다. 따라서 구현의 세부 내부 구조나 성능 수치는 주장하지 않는다.

## 프로젝트 맥락

리모트 세미나는 웹 브라우저에서 진행하는 온라인 웨비나 서비스다. 물리적인 장소와 참가자 확보의 제약을 낮추고, 진행자와 청취자가 실시간 세미나를 운영·참여할 수 있도록 하는 제품이었다. 2019년 4월부터 2021년 4월까지 React·Redux 기반의 웨비나 기능과 관리자 화면 신규 개발에 참여했다.

미디어 연결은 MCU 기반으로 제공됐고, 제품 화면에서는 세미나 진행·작성·미리보기·관리처럼 서로 다른 화면이 같은 진행 상태를 다루어야 했다. 이력에 남은 기능 목록은 단순 화면 추가가 아니라, 작성·운영·참여 흐름을 각 역할에 맞게 이어 붙인 작업 범위를 보여준다.

## 맡은 개발 범위

### 세미나 작성과 진행 기능

- 세미나 기본 양식과 설문 기능을 개발했다.
- 위지위그 편집기를 서비스 요구에 맞게 커스터마이징했다.
- 파일 다운로드와 카운트다운 기능을 구현했다.
- YouTube 커스텀 플레이어를 개발하고 반응형 화면을 구성했다.

### 관리자와 데이터 모델

- React·ant-design·Rematch 조합의 관리자 페이지 신규 개발에 참여했다.
- Redux 및 Redux-Saga를 사용해 화면 상태와 비동기 흐름을 다뤘다.
- Normalizr로 세미나 관련 데이터를 정규화했다.

### 여러 브라우저 창의 동기화

세미나 운영 중에는 방송인·청취자 화면, 글 작성·미리보기 화면처럼 같은 진행 정보를 서로 다른 창에서 보여줘야 하는 경우가 있었다. 이 작업에서는 BroadcastChannel을 이용해 브라우저 창 사이의 실시간 데이터 동기화를 구현했다.

당시 기록에는 다음과 같은 화면 간 동기화 사례가 남아 있다.

- 방송인과 청취자 사이의 카운트다운 동기화
- 세미나 글 작성과 미리보기 사이의 실시간 반영
- 설문지 작성과 미리보기 사이의 실시간 반영

이러한 흐름에서 정규화는 여러 화면이 같은 엔터티를 다룰 때 중복된 상태를 줄이고, 동기화는 화면마다 진행 정보가 달라지지 않게 하는 데 필요한 경계였다. 다만 공개 자료만으로는 실제 메시지 형식·충돌 처리·운영 규모를 확인할 수 없으므로 여기서는 역할 범위만 기록한다.

## 프로젝트에서 얻은 경험

신규 서비스의 기능을 추가하면서 사용자 요구에 맞춘 운영 기능을 설계·구현했고, 반응형 UI와 브라우저 API를 실제 서비스 흐름 안에서 다뤘다. 당시 회고에는 여러 기업의 도입과 사용을 보며 기능 개발의 보람을 느꼈다고 남겼지만, 도입 수나 운영 성과를 검증할 자료는 없으므로 수치로 확장하지 않는다.

## 공개 범위

Notion 이력에 남아 있던 서비스 주소는 현재 응답을 확인하지 못해 카드의 공개 링크로 유지하지 않았습니다. [포트폴리오 요약](/projects/remote-seminar)에서 기간·제품 맥락·역할 범위를 확인할 수 있습니다.

이 글은 Notion 이력의 제품 맥락과 업무 목록을 공개 가능한 범위에서 옮긴 기록입니다. 비공개 코드·세미나 데이터·운영 지표는 포함하지 않습니다.
