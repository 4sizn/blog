## 🎉 [4sizn Blog] v1.0.0 릴리즈

> 📅 릴리즈 날짜: 2026-02-03

![2026-02-03 당시 블로그의 릴리즈 목록 — 자동 동기화가 만든 첫 두 건](/static/blog/releases-2026-02-03.jpg)

v1.0.0을 공개합니다. 만든 것들의 릴리즈를 블로그로 옮겨 적는 일을 자동화했습니다.

## ✨ What's New

### 릴리즈 자동 동기화

프로젝트마다 릴리즈를 내지만 블로그에 옮겨 적는 것은 매번 잊었습니다. 릴리즈 노트를 두 번 쓰는 일이기도 했습니다.

GitHub Actions가 매일 오전 9시에 추적 목록의 저장소를 확인해 새 릴리즈를 글로 만듭니다. 목록에 저장소를 여러 개 넣을 수 있습니다. 기다리지 않고 수동으로 돌릴 수도 있습니다.

### 템플릿 기반 생성

글의 형식을 바꾸려면 스크립트를 고쳐야 했습니다. 문구 하나 바꾸는 일에 코드를 건드리는 구조였습니다.

마크다운 템플릿과 코드를 분리했습니다. 스크립트는 placeholder만 채우므로 형식을 바꿀 때는 템플릿만 고치면 됩니다.

### 커밋 프리픽스 분류

릴리즈 본문의 conventional commit 프리픽스를 읽어 기능·버그 수정·개선 섹션으로 나눕니다. 해당 항목이 없는 섹션은 지웁니다.

## 🔧 Improvements

- 파일명과 제목에 `YYYY-MM-DD` 날짜를 붙여 시간순으로 정렬되게 했습니다

## 🐛 Bug Fixes

- 페이지가 무한히 새로 고쳐지던 문제를 고쳤습니다
- permalink 처리 문제를 고쳤습니다

## ⚙️ Under the Hood

`CLAUDE.md`에 개발 가이드를 적었습니다. 개발 환경 설정부터 빌드와 배포까지의 절차를 한 파일에 모았습니다.

## 🔜 What's Next

이다음 v1.0.1에서 버전 관리 정책을 세우고 동기화가 스스로를 다시 트리거하지 못하게 막았습니다.

그리고 2026년 8월, 이 시스템에서 결함 두 개를 찾았습니다. 워크플로가 스크립트와 다른 경로를 검사해 새 릴리즈가 커밋에 도달하지 못했습니다. 최신 릴리즈 하나만 조회해 같은 날 두 번 낸 릴리즈 중 앞엣것이 묻혔습니다. 둘 다 고쳤고 묻혀 있던 두 건도 되찾았습니다.
