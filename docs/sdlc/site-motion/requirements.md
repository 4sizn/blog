# 4sizn Blog 시각적 모션 개선 요구사항 정의서

## 1. 배경 · 목적

사용자는 `/Users/hsshin-rsupport/Documents/lotus/4sizn-blog`의 페이지를 SDLC로 진행하면서 **시각적 애니메이션을 중점**으로 다뤄 달라고 요청했다. 대상 라이브 페이지는 `https://4sizn.github.io/blog/`로 확인했다.

현재 `blog/index`는 Quartz의 `HomeCategoryThumbnails`로 Log, DEV/Daily_Read, Releases를 카드 목록으로 보여준다. 페이지 로드 시 CSS `fade-up` 애니메이션은 실제로 적용되지만, 카드의 상호작용은 테두리와 제목 색상 전환에 그친다. 특히 기본 썸네일이 여러 카드에서 반복되어 스크롤 중 콘텐츠 묶음과 카드의 개성이 약해 보인다.

목표는 정보 구조와 글 URL을 보존한 채 다음을 달성하는 것이다.

1. 사용자의 시선을 카테고리, 카드, 클릭 가능한 다음 행동 순서로 자연스럽게 이끈다.
2. 모션을 장식이 아니라 위계, 탐색 피드백, 콘텐츠 전환의 신호로 사용한다.
3. 기존 다크/라이트 모드 및 읽기 중심 편집 디자인을 해치지 않는다.

## 2. 범위

**In scope**

- `blog/index`의 카테고리 블록, 게시글 카드, 썸네일, `더 보기` 링크에 대한 모션/상호작용 개선
- 기존 로드 진입 `fade-up` 모션의 중복 여부 점검 및 카테고리별 순차 진입으로 정리
- 카드 hover, focus-visible, active 상태에서 클릭 가능성과 콘텐츠 관계를 전달하는 모션
- 화면 진입 기반의 카테고리 reveal과 대표 카드의 이미지 처리 규칙
- `prefers-reduced-motion`에서 모든 자동/스크롤 모션을 정적 상태로 축소하는 동작
- 다크 모드와 라이트 모드에서 모션 종료 상태, 대비, 포커스 표시를 확인하는 E2E 증거
- 변경된 화면의 실제 실행, 스크린샷 캡처, 이미지 자체 검증, macOS Preview 표시

**Out of scope** - 이번에 하지 않는 것

- 글 본문, 글 URL, 디렉터리 구조, Explorer/Graph의 정보 구조 변경
- Quartz 엔진 업그레이드 또는 프레임워크 교체
- GSAP, Motion 등 새 런타임 애니메이션 의존성 추가. 설계에서 필요성이 입증되고 사용자가 승인할 때만 별도 범위로 다룬다
- 자동 재생 비디오, 배경 파티클, 무한 marquee, 마우스 추적 효과, 스크롤 하이재킹
- Home/About/Projects의 시각 개편. 다만 재사용 가능한 CSS 토큰은 허용한다
- 콘텐츠별 새 이미지 제작. 기본 썸네일 반복 개선은 우선 배치/처리 규칙으로 해결한다

## 4. 기능 요구사항

| ID    | 요구사항                                                                                | 우선순위 | 출처                             | 수용 기준                                                                                                                                                                                        |
| ----- | --------------------------------------------------------------------------------------- | -------- | -------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| FR-01 | `blog/index`의 각 카테고리 블록은 viewport에 최초 진입할 때만 순차적으로 나타나야 한다  | 필수     | 사용자 구두 + 라이브 페이지 감사 | Log, DEV/Daily_Read, Releases 블록 각각에서 제목과 카드가 `opacity`/`transform`만 이용해 500ms 이내에 진입한다. 페이지 재진입 또는 SPA 탐색 후 같은 블록이 반복 점멸하지 않는다                  |
| FR-02 | 게시글 카드는 hover, keyboard focus, active 상태에서 동일한 탐색 피드백을 제공해야 한다 | 필수     | 사용자 구두                      | 마우스 hover와 `Tab` focus에서 썸네일의 미세 확대 또는 이동, 카드 표면/테두리 전환, 제목 강조가 확인된다. `Enter`로 링크가 열리고, active 상태는 최대 120ms 이내의 transform 피드백으로 끝난다   |
| FR-03 | `더 보기` 링크는 링크 목적과 이동성을 모션으로 전달해야 한다                            | 필수     | 라이브 페이지 감사               | hover/focus 시 텍스트와 방향 표식의 짧은 이동이 있고, reduced-motion에서는 색상·밑줄·outline만 남는다. 링크의 접근 가능한 이름은 기존처럼 카테고리명을 포함한다                                  |
| FR-04 | 기본 썸네일 반복이 스크롤 리듬을 해치지 않도록 카드 이미지 처리 규칙을 둔다             | 필수     | 라이브 페이지 감사               | `socialImage`가 없는 카드가 연속되어도 최소한 카드별 hover/focus에서 동일 이미지가 과도하게 움직여 시선을 빼앗지 않는다. 이미지 비율, 예약 공간, alt 대체 정보와 본문 가독성이 유지된다          |
| FR-05 | 기존 page-load `fade-up`과 신규 모션은 하나의 일관된 모션 언어로 정리해야 한다          | 필수     | 코드 감사                        | duration, easing, rise distance, stagger가 CSS 변수 또는 한 곳의 토큰에서 정의된다. 한 묶음의 stagger 총합은 500ms 이하이며, `top`, `left`, `width`, `height`를 애니메이션하지 않는다            |
| FR-06 | reduced-motion 사용자는 정적인 레이아웃과 즉시 사용 가능한 링크를 받아야 한다           | 필수     | 접근성 요구                      | `prefers-reduced-motion: reduce`에서 reveal, image scale, 이동, 자동 애니메이션이 실행되지 않는다. 카드와 링크의 hover/focus 대비 및 keyboard 사용성은 그대로 남는다                             |
| FR-07 | 기존 탐색 구조와 SEO 경로를 보존해야 한다                                               | 필수     | 보존형 리디자인 원칙             | `blog/index`, `blog/log`, `blog/dev/Daily_Read`, `blog/releases` 링크 대상과 텍스트 라벨이 변경되지 않는다. JavaScript가 비활성인 정적 HTML에서도 모든 카드 링크가 존재한다                      |
| FR-08 | 결과는 실제 브라우저에서 시각적으로 검증되어야 한다                                     | 필수     | 사용자 가시 산출물 규칙          | 다크, 라이트, reduced-motion 각 1개 이상의 최종 화면을 캡처한다. 캡처를 에이전트가 이미지로 확인한 뒤 macOS Preview로 연다. 카드 focus 또는 hover와 카테고리 reveal이 최소 한 장의 증거에 담긴다 |

## 6. 제약

- Quartz v4.5.2 및 Preact 기반 정적 생성 구조를 유지한다.
- 기준 컴포넌트는 `quartz/components/HomeCategoryThumbnails.tsx`, 스타일은 `quartz/components/styles/homeCategoryThumbnails.scss` 및 `quartz/styles/custom.scss`다.
- 기존 global `fade-up`은 실제 라이브에서 380ms/460ms로 실행 중이다. 새 구현은 이를 중복하거나 전체 페이지를 장시간 순차 표시해서는 안 된다.
- 현재 프로젝트의 `Space Grotesk`, `Pretendard`, `Inter`, 에메랄드 accent, 다크/라이트 테마 토큰을 존중한다.
- 모션은 사용자가 읽을 텍스트와 링크를 가리지 않으며, 자동 재생/무한 루프를 도입하지 않는다.
- 코드 변경은 이 요구사항 및 이후 설계 승인 후에만 시작한다.

## 7. 전제 · 미확인

> [!question] 이번 변경의 최종 대상은 `blog/index` 한 페이지인가, 아니면 Home/About/Projects에도 같은 모션 시스템을 적용해야 하는가?
>
> 이 요구사항은 사용자 메시지와 실제로 점검한 라이브 URL에 따라 `blog/index`만 대상으로 삼는다. 다른 랜딩 페이지까지 확대하면 영향 컴포넌트, E2E 범위, 성능 예산이 달라진다.

> [!question] 카드별로 겹치지 않는 새 대표 이미지를 제작하는 작업을 이번 범위에 포함할 것인가?
>
> 현재는 반복 기본 썸네일을 모션이 과장하지 않도록 처리하는 데 한정한다. 이미지 제작은 콘텐츠/자산 작업이므로 별도 승인 없이 포함하지 않는다.

**전제** - 사실로 가정하고 진행하는 것

- 라이브에서 확인한 `blog/index`의 Log, DEV/Daily_Read, Releases 구조와 기존 URL은 유지해야 한다.
- 사용자 요청의 "시각적 애니메이션"은 과도한 장식이 아닌 탐색과 위계에 기여하는 모션을 뜻한다.
- 기존 CSS 중심의 Quartz 구조가 FR-01~FR-06을 충족할 수 있다. 설계 중 한계가 발견되면 새 라이브러리 도입이 아닌 대안을 먼저 제시한다.
